# Compare effective Desktop settings

**project-parity** — In MacBook main create a uniquely titled reference task for the test project using native defaults. Record thread ID, account identity (redacted stable comparison), selected model, effective sandbox and approval settings, available MCP servers/tools and enabled plugin IDs. Exercise one benign permission-sensitive file operation in a case-owned scratch path and one read-only configured tool or plugin action. Quit main and confirm process exit. Use the [installed runner](../installed.md) to dispatch a different uniquely titled task in the identical project without model, account or permission overrides. Confirm the independent backend writer, then repeat the reference probes.

**same-settings** — For this project each effective value and capability result matches the reference, including full access when enabled. Compare set membership by ID and effective account by stable identity. Record unavailable fields as gaps; the same config file alone cannot establish effective parity.

**listed-in-main** — Launch main normally, refresh its task list, and locate the independent task by its title without opening a deep link. Select it and verify its ID and unique history marker.

Baseline expectation: the main and shared routes can already agree. Private-route parity requires the new dispatch path.
