# Remote Desktops stay connected

Use the [MacBook setup](../installed.md). On the mini, leave its main and independent Desktops connected through remote hosts to the MacBook's shared service before dispatch through parent archive. Bind each proxy and connection to its Desktop PID and the MacBook daemon. Verify liveness with an unrelated shared task. Start passive connection-attributed observation before dispatch. Never select or explicitly resume a subject on the mini. Generate identifiable progress markers before and after child creation. Record the actual child edges and executing backend.

**remote-family (D1)** — Exercise one active parent while its child runs, after child completion and after parent completion. Repeat with overlapping siblings and mixed completed/interrupted child turns, then exit the MacBook independent process.

**no-remote-hold** — For the observed interval and each root and descendant, the complete trace shows neither remote client acquiring a subscription or writer. Alternatively demonstrate disjoint server ownership throughout, with every remote connection accounted for, a complete private-backend client inventory and no shared writer for these IDs. Check the mini receives live progress for the shared control while private live markers are absent. A final clear lock, silent UI or one PID snapshot leaves interval attribution open.

**subtree-archive** — With the same remote connections alive, archive the completed root once in MacBook main. Read back each recorded ID in archived history and its absence from active history. Retest shared-control liveness.

Baseline expectation: a shared-backend child can acquire an automatic remote subscriber. A passive root alone cannot exercise this case.
