# Installed MacBook runner

Drive the paired acceptance MacBook from the Mac mini. Use `ssh macbook` and verify `id -un` returns `wh`. Use its existing Codex home, login, daemon and ARC LaunchAgent. Keep credentials on that host. Stage the case checkout and its locked Node dependencies there (the subscriber imports ws). In a MacBook SSH shell:

```sh
driver="$PWD/behavior/cases/installed.py"
run=$(python3 "$driver" init) || exit 1
h() { python3 "$driver" "$run" "$@"; }
h login
h arc-start
```

Read the loaded GUI LaunchAgent with `launchctl print gui/$(id -u)/com.whzxc.agent-remote-control`. Compare its ARC_STATE_DIR to the plist and installed CLI status, and confirm the original device is online from the mini. Record the original task settings before `h configure`. Record native home, shared control-socket peer PID/start and that running executable's version. The prompt-unlock given is the MacBook shared 0.163.0 with its default 1,800-second grace ignoring per-thread zero. Preserve it through the trial. The bundled client can report a different version.

**Install and restore.** Before replacing ARC, record installed build, signature, pairing and running processes. Back up the bundle on MacBook with `ditto -c -k --keepParent "/Applications/Agent Remote Control.app" "$run/original.zip"`, test the archive, and record its checksum. Back up ChatGPT likewise before an update trial. Stage the signed candidate on the same volume, verify checksum against the mini and run `codesign --verify --deep --strict`. Use the installed update action for version-change cases. For manual bundle replacement stop the identified ARC job and Core, preserve the old bundle, install the verified staged bundle and reload the same plist with launchctl bootstrap after bootout. Start through the LaunchAgent. Verify the actual running build, state, health and pairing. For each independent upgrade replay restore the older bundle and use fresh uniquely titled tasks. After the run restore the backed-up app(s) by the same sequence, verify original versions and signing identities, restore saved settings and original app/process state. Export the evidence to the mini. Keep unrelated sessions, homes and logins intact.

**Dispatch.** Quit the MacBook main Desktop before `h dispatch "HB unique title" "Reply with the unique marker."`. Confirm its process exited. A resident main Desktop can take dispatch through follower IPC. Resolve pending creates with `h ctl receipt '{"requestId":"…"}'`. Record receipt, original turn/thread IDs, independent PID/profile/window and actual backend writer PID/endpoint. Save `h instance > "$run/instance-before.json"`. For private-route cases verify the writer belongs to the independent backend and the shared daemon is distinct. For pre-change or fallback cohorts verify the shared writer. Confirm native spawn relationships and terminal states for every child. A real running gate, failed turn or held child requires positive evidence. After all seeds, `h main-start` opens main in the MacBook's own profile. Verify it has a distinct PID/window and targets an unrelated task before the probe. Leave the mini's remote-host Desktops connected for the remote cohort.

**GUI.** From the mini select the paired MacBook in ARC `devices` and forward `screen` via `device`. For example, forward `{"op":"device","args":{"device":"<paired ID>","op":"screen","args":{"action":"windows"}}}`. List windows, match PID, window ID and task title/history, raise the exact window, verify frontmost and inspect its AX tree before sending keys or pressing a control. Verify resulting thread and UI state after each action. For the old handback cases use this flow for the status text, enabled Reopen, Quit, parent send and archive. Use the native window close control for the resident-process case. For a crash use `h crash` after recording the instance. Collect separate signed builds for an ARC version-changing update.

**Verdicts.** Record case ID, exact varied inputs, build and per-thread evidence. For each applicable then ID report pass, fail, or evidence gap for this trial. Record unexercised variants separately. A missing starting condition or unavailable witness is a gap. Record an observed contradiction after the given and action as a failure.

## Timing and readback

Use the MacBook monotonic clock for both ends. The local driver provides `h stamp <event> <threadId>` for operator bookmarks. For the 30-second cases, run `h watch-exit > "$run/exit.json"` in a second case shell and wait for its armed message before triggering the exit and arm a read-only native `turn/completed` observer before releasing the provider gate. An alternative is to timestamp gate release (earliest possible completion) and the first confirmed terminal read for that original turn (latest possible completion). Using both bounds avoids timing a late observation as the start of a new 30-second window. Do not resume or subscribe to an unloaded thread to observe the transition. Record the exit/terminal event at observation, together with its observation latency. A timestamp taken after noticing a closed window, reopening the panel, or reading a later receipt cannot start the timer.

## Holds and handback

For the existing shared-daemon witness cases use a confirmed legacy or shared-fallback subject. An independent private writer and a subscriber on the shared endpoint cannot seed a co-subscribed family. Before dispatch, select which subjects will be held by ARC alone and which will retain another subscriber. For the latter, start `h subscribe "$thread"` from a second terminal in the MacBook SSH session (or via the remote side's SSH login with the same driver and case root). It opens its own connection to the case daemon, verifies the daemon home at handshake and subscribes once. Keep it open through the ARC checks. Only the holder-side operator releases it, by pressing Return after the observations. The native reply confirms whether this client still had its subscription. Preserve the holder's output and the daemon identity. Use an additional unrelated task as a control.

Use `h locks "$parent" "${children[@]}"` with a shell array containing the actual child IDs. The driver probes only the case home's native locks and timestamps each result. Compare with task detail or `h ctl codex_owner '{"threadId":"…"}'` on the same IDs. Distinguish the ARC hold, the kernel writer, and ARC's displayed handback decision in the evidence ledger:

- With a sole ARC holder, observe the last held and first clear samples, the displayed handback status, and the actual main Desktop actions below.
- With a surviving client, the kernel lock can stay held past 30 seconds. Record the ARC-side release time separately. Use a passive, connection-attributed native trace if the runner has one: bind connections to the independent instance, ARC Core and witness, and record acknowledged per-thread unsubscribe or disconnect, outstanding subscriptions and any later reacquisition. A request without an acknowledgement is insufficient. The installed public owner query cannot enumerate per-client subscriptions behind a shared process. If that trace is unavailable, report the exact ARC-release timing as unobservable and still check the holder display, witness continuity and later handback.
- Apply the 30-second bound to ARC dropping its own hold after process exit or natural turn termination. Use timestamp bounds if sampling straddles the deadline. A daemon can retain a writer after a client unsubscribes. A held lock at the deadline, by itself, leaves ARC-specific timing unknown. The independent client's release, the daemon's eventual unlock and the operator's send/archive are separate events. Keep each thread's evidence even when a sibling succeeds.

After an independent lock probe reports clear, observe the handed-back mark before main reacquires the writer. Send a unique marker **to the parent** from main and verify the accepted message in that parent after refresh. When the new turn finishes, choose Archive **once on the parent** in main Desktop. Refresh and verify the exact parent and every child in Archived and absent from active history. An equivalent second freshly seeded family may be used to exercise parent archive without a preceding send. Never use direct subagent input or separate child archive operations as probes.
