# Codex 自己卡住了，ARC 把客户端救了回来

[English](../../stories/codex-client-login-recovery.md) | **简体中文**

*2026 年 11 月 18 日，一次从网页发起的客户端登录救援。*

平时电脑上遇到问题，我习惯先找 Codex。查日志、看配置、跑命令，很多事情在对话里就能接着往下处理。

这次，轮到我平时用来跑 Codex 的 ChatGPT Windows 客户端出问题了。

打开之后，页面只剩下一句：

> 未能加载账户信息。请检查网络连接后重试。

重启客户端，点“重试”，画面还是没变。

这就有点尴尬了。平时帮我处理电脑问题的那个工具，现在自己进不了主界面。

好在，同一台电脑上的网页版完全正常。我就在网页里把截图发了过去，补了一句：网页版能用，我们现在就在这台电脑上沟通。

原本是想请它分析一下原因，结果聊着聊着，客户端真的被救回来了。ARC 在这件事里帮了大忙。

## 客户端卡住了，电脑还接得上

关键就在这里：桌面端登录失败时，ARC 仍保留着可以读取本机状态、执行命令的通道。

网页里的助手通过 ARC 查看进程和客户端日志，又从本机日志数据库里找到了更具体的错误。它还确认了这些记录来自桌面客户端自己启动的本地服务，避免把另一处账户检查的结果当成这次故障的原因。

界面上笼统的“检查网络”，到了日志里，变成了两个明确的线索：

| 检查对象 | 实际结果 | 能说明什么 |
| --- | --- | --- |
| 桌面端的模型列表请求 | `401 Unauthorized`，`token_expired` | 当前访问令牌已经过期 |
| 自动刷新登录凭据的请求 | `400 Bad Request`，`Failed to refresh token` | 客户端没有成功取得新的凭据 |

问题收窄了：旧凭据过期，自动续期又没成功，账户信息就一直加载不出来。

同机网页版正常，和这个判断并不冲突。浏览器里的登录会话还在，桌面端的认证却已经卡住了。

至于刷新请求为什么返回 `400`，现有证据还不足以继续下结论。能确认的是这条认证失败链路。

中间 ARC 也出现过短暂的连接超时。连接恢复后，检查继续进行，最后拿到了能指导下一步操作的证据。

## 重新登录，还有最后一步

接下来，要让客户端重新拿到有效的登录凭据。

眼前的错误页只有一个“重试”，正常的账户入口用不上。助手核对了当前安装的客户端，以及它使用的原生认证存储，找到安装包自带的登录程序，通过 `codex login` 发起官方浏览器授权。

随后，我在浏览器里按官方登录流程完成了账户授权。[Codex 的认证文档](https://learn.chatgpt.com/docs/auth)介绍了这种浏览器登录方式；[Windows 文档](https://learn.chatgpt.com/docs/windows/windows-app)也说明，桌面应用与原生 Windows Codex 默认共用本机的 Codex 主目录。这次是在核对当前机器的实际配置之后，才采用了这条恢复路径。

随后，登录程序返回：

```text
Successfully logged in
```

然后继续检查，发现桌面端已经检测到新的认证信息。此前失败的同一个模型列表接口，返回了 `200 OK`。

但窗口还停在旧的错误页上。

这个细节很关键：后台的登录状态已经恢复，眼前的界面还没有跟上。于是，再重启一次桌面客户端。

这一次，项目列表、模型选择和输入框都回来了。

| 恢复检查 | 看到的结果 |
| --- | --- |
| 官方授权 | 登录程序报告成功 |
| 受保护接口 | 原先失败的模型列表请求返回 `200 OK` |
| 实际窗口 | 重启后进入正常主界面 |

到这里，这次救援才算完成。重新授权、接口响应和实际界面，三个地方都对上了。

## 这次真的想好好夸一下 ARC

平时用起来顺手，很容易忽略一个问题：如果帮我排障的工具自己卡住了，我还能找谁？

这次，网页版还能继续对话，ARC 还能接到这台电脑。于是，查看日志、执行恢复、重启客户端、检查结果，这些事情都能接着做。

我把现象讲清楚，再在浏览器里完成账户授权。其余的检查和恢复，助手就能沿着实际的进程和日志往下做，通过 ARC 把操作落到本机。拿到“登录成功”之后，它还会回到接口和窗口，看看客户端到底恢复了没有。

这份体验很实在。

当然，这次能救回来，有它的条件：电脑还可以访问，ARC 的读取和执行通道还能工作，而登录故障也能通过重新授权解决。但在最需要它的时候，这条通道确实帮上了忙。

平时是我让 Codex 帮忙处理电脑上的问题。这次，ARC 帮我把那个处理问题的客户端也救了回来。

这个能力，值得认真夸一次。
