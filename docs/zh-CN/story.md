# 为什么做 ARC

[English](../story.md) | **简体中文**

我想直接讨论一个项目，不用先把当前状态复制到聊天里。文件已经改过，决策已经变化，Codex 已经做完一轮，对话却还在依据之前的情况推理。

ARC 最初让 Chat 读取电脑上的真实状态：文件、项目结构和 Git。接下来是把讨论变成工作。既然 Chat 能看见项目，就可以把明确任务派给 Codex，再读取结果。

这样，ChatGPT Chat 成了独立的思考空间。遇到复杂设计，可以用它的 Pro 推理选项确定方案，再把约定好的计划交给 Codex，不用把整段讨论搬进另一个窗口。

但回程仍然打断工作。我还得发现 Codex 已经完成，把结果带回来，再问下一步。

Claude + Codex 闭环补上了这一段。Claude 读取当前事实并派任务，Codex 在本机执行，ARC 通知绑定的 Claude Code 云端会话，Claude 接着审查和推进。目的很简单：让讨论和执行一起向前，离开电脑也能继续。

[试试这个闭环](getting-started.md)。
