# 远程查看 ARC

通过已有的 HTTPS 连接或 ARC 中继打开只读状态页。网页复用应用端的拓扑、侧栏、账号、会话列表和任务详情，写操作控件禁用。

## 获取访问链接

在运行 ARC 的电脑上执行：

```sh
arc cli call browser.access
```

从 `result.links` 中找到连接地址，在浏览器中打开以 `/?key=arc_…` 结尾的完整链接。ARC 会将 key 保存到 LocalStorage，并立即从地址栏清除。登录后可以收藏不带 key 的地址。
首次通过本机接口获取时会生成 key，重启 ARC 后继续有效。这个 key 适用于当前 ARC 实例的 HTTPS 连接和中继。

首次访问需要有效的 key 链接。ARC 同时设置持久的 Secure、HttpOnly、SameSite=Strict 会话 Cookie，后续直接打开域名或刷新即可访问。
接口请求使用保存的 key，页面、资源和实时流通过会话 Cookie 认证。缺少有效凭证时，返回正文为空的 HTTP 401。响应禁止 HTTP 磁盘缓存和发送来源地址。当前页面在内存中复用未变化的读取结果；实时状态通过精简流同步，未变化的读取不传输响应正文。
ARC 入口日志不会记录 key 或请求查询参数。

## 更换 key

```sh
arc cli call browser.access.rotate
```

使用返回的 `result.links` 中的新链接。旧链接和旧会话随即失效，已有实时连接会在两秒内的下一次认证检查时关闭。

## 配置连接

ARC 管理的 HTTPS Tunnel 通过现有地址和进程转发网页。ARC 中继链接包含实例路径，例如 `/u/<instance>/`。
自定义反向代理需要把 `/`、`/assets/*` 和 `/view-api/*` 转发到 `/mcp` 所在的 ARC 入口监听地址，并允许 `/view-api/*` 流式响应。
本地管理监听地址继续保持私有。

## 限制

- OpenAI Secure Tunnel 承载 MCP，无法提供网页。只有这类连接时，需要添加 HTTPS 连接。
- 浏览器支持查看状态和展开任务详情。发送消息、回答请求、修改配置、主动刷新上游额度和启停连接均不可用。
- 本地图片遵循任务资源访问范围，无法从网页调用本机文件管理器打开文件。
- ARC Core 和所选 Tunnel 需要保持运行。连接中断后，页面保留最后一次快照并显示连接错误。
- 从源码构建时，需要先构建前端，再编译 Core，以嵌入网页资源。正式桌面和 Linux 构建入口会自动完成这一步。
