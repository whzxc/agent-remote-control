# UI conventions

[Remote link design and phases](remote-link.md) · [Development](development.md) · [Architecture](architecture.md)

React renders. Tauri/Rust owns configuration, connections, tasks, authentication, native windows, and updates. The main window shares semantic tokens, preferences, and controls.

Activity model badges retain their intrinsic width. Codex project labels use the native project catalog, shared with project resolution through a 30-second cache. Explicit project IDs take precedence; directory matching requires an unambiguous deepest root. The filesystem directory remains separate from its display name. Task details show the project beside the Agent name, with duration, source, and model in the metadata row. All task surfaces share running, waiting-for-input, completed, failed, interrupted and unconfirmed execution states. Activity absence and native idle metadata are not completion evidence. Historical dispatches use their bound turn, never a later turn in the same conversation. Model and effort share one pill. Conversation card height follows its content, with equal padding on every side.

Timeline groups follow native turn IDs regardless of dispatch origin. External Codex history remains readable after the activity monitor no longer retains the session. History read failures stay visible and retryable instead of becoming a cached partial result. Only actual coverage limits show a partial-history notice; external origin alone does not imply missing history. Incomplete coverage is distinct from a clipped output excerpt, whose notice stays beside that output. Every turn keeps a card surface in both disclosure states, including the latest and running turn. Clicking the title row toggles the turn; its right edge shows that turn’s execution duration. The task header sums known turn execution spans and excludes gaps between turns. Native lifecycle timestamps backfill historical turn timing; missing timing is not inferred from the time the panel opened. Work blocks have no outer border or extra padding. Reasoning rows show their available summary and disappear when it is empty.

The timeline owns vertical scrolling. Tables, code blocks, file lists, diffs and command logs scroll horizontally within the stream and expand to their full content height. Wheel gestures over these blocks send horizontal deltas to the block and vertical deltas to the timeline, including diagonal gestures. Unconsumed boundary events retain native scroll chaining.

## Homepage and layout

The homepage uses the ARC mark and arc-shaped earcup connections in both themes. Five two-color palettes are ARC, cyan/blue, pink/purple, red/orange, and yellow/green. ARC retains orange and blue-purple gradients. Other palettes apply to the control-source and Agent sides.

Portrait orientation, rails and panel placement follow [Portrait layout](portrait-layout.md). The geometry below describes landscape.

ui/topology/solve.ts is the pure geometry owner. Wings share a mirrored algorithm. Initialize SVG and ResizeObserver after container refs commit. Solve only after a nonzero real viewport exists. Resizing recomputes geometry with spring transitions. Ports follow target direction with angular spacing. Earcups/outer arcs fit port ranges. Primary/secondary tentacles widen toward the root by arc length. Connecting shows root fade and moving dashes. Errors use semantic error color and background breaks. Disconnected/disabled nodes have no primary line and faded icons/names. Center-dot entry points do not participate in connections. Primary tentacles end at earcups with space before the dots.

The animator integrates stable-key center/radius, DOT scales, earcup extent, node position/scale/opacity/ports, wire opacity/availability, outer arcs, and task primitives with stiffness 210, damping 26, and roughly 8ms substeps. Each frame recomputes tentacles/arcs. One SVG draws connections. HTML nodes and fixed-size bubbles receive same-frame transforms through refs. The top connection toggle follows the animated hub's horizontal center in the same frame while retaining its top offset. Topology animation neither renders React each frame nor reads node DOM coordinates or uses layout projection. rAF stops when stationary. reduced-motion switches positions directly and stops flow. Runtime media-query changes apply immediately.

Platform, connector, Agent and Agent-profile nodes share one size, defaulting to 42px and adjustable from 32 to 60px. Activity and hierarchy do not change icon size. Icons, quota rings, endpoints, and outer arcs scale together. Idle Agents may fade and indent when tasks occupy the wing; their size remains unchanged. Row and column compression accommodates limited space.

Wings independently compress rows. Active row height fits the sum of task heights and inter-task gaps, with 12px gaps between Agent rows. Scene height is max(viewport height, larger wing height + 140). Column spacing defaults to 2.6, adjustable 2.0-3.2. Columns center vertically. Horizontal fitting keeps the hub at the viewport center while both wings fit inside the viewport margins or dock boundary. A wing reaching its boundary displaces the hub only as far as needed. When translation alone cannot fit both wings, fitting first reduces the ring to at least 0.6 of its preferred radius. If space is still insufficient, both column distances compress by an equal ratio down to the configured minimum. Returning space restores the centered layout. The viewport margin defaults to 40px. Remaining overflow preserves the left wing and clips the right, with vertical scrolling. The center retains brand assets and earcup spacing.

The bottom navigation contains Platforms, Permissions, and Settings. Tasks remain accessible through Agent panels; request logs have no standalone UI page. The hub's upper arc opens a centered connection panel with connection URLs, status, editing, removal, and Add connection. With no external connections, the arc is broken and exposes Add connection directly. Hover and keyboard focus lift the arc with a spring; reduced motion skips the transition. One device connection is recommended for all products and platforms; existing multiple connections remain manageable.

Node names stay below and ellipsize. Add/manage controls occupy the ARC endpoint dots outside sorting. Do not add trailing helper buttons, coordinates, or empty-column placeholders. Pointer Events update solver drag inputs directly. Items follow both axes, but only vertical changes reorder. Other items yield through springs. Dragging does not change center balance/column spacing. Release saves order and springs back to the column. Homepage dragging uses no Motion Reorder or layout projection. Escape/pointer cancellation restores order. Source order persists. Enabled Agent order is shared with management. Hidden items keep relative order. Task order is frontend-local. Pending tasks remain first. Top toggles keep simple tactile state changes without text, outer glow, or star decoration.

Collapsed queues show up to five slots, with overflow summarized in the fifth. Unfinished tasks remain visible before completed tasks. ## Task detail projection

Task details prioritize pending decisions, final replies, phase prose, the latest plan, merged tool activity, and one live thinking line. Successful turns fold their process; failed and interrupted turns start expanded and honor subsequent disclosure choices. Process summaries align their text insets with final-reply cards and leave a full row gap above expanded content. Previous turns start collapsed and their arrows follow the expanded state. Previous-turn and process-summary arrows stay at the right edge. Tool groups open automatically only while running and honor manual disclosure choices. Each tool invocation row toggles its details, which start collapsed even after failure. Running commands retain their live log preview. Pending execution questions and permission requests show an input dock for every source, including ARC-local turns, while execution is running. The header derives its attention state from the same answerable, unsubmitted request set. Resolved history overrides stale activity requests. Question drafts survive closing the narrow-panel sheet. The dock disappears after resolution or execution ends. Prompt source labels use recorded provenance; prompts without a source omit the entire metadata row. Review feedback is optional supplementary information loaded only when expanded. Missing feedback creates no awaiting-review state. Read failures remain inside that supplementary region and do not affect execution state, sorting, notifications or task controls. Control sources own dispatch, queue changes, interruption, and review. Task details expose no composer, purpose selector, stop, or review actions. The latest failed turn offers Retry inside its outcome card; the latest interrupted Codex turn offers Resume there. Retry sends an explicit continuation in the same task and retains its receipt requestId on uncertain retries. The continuation asks the Agent to inspect existing work and avoid repeating side effects instead of replaying the original prompt. Source chips show only the source icon and name. ## Execution evidence and supplementary feedback

Homepage bubbles, Agent rows, detail headers, topology wires and bound source-dispatch rows use the same execution-state projection. Only a current activity observation establishes running or waiting for input. A recorded terminal turn establishes completion, failure or interruption. A disappearing activity retains an unconfirmed task until native history supplies its result. An idle runtime alone establishes no outcome. Background history reads are shared per Agent/task and do not acquire execution ownership. New turns invalidate the previous turn's live presentation.

Only running tasks show thinking, command, file, tool or response phases. Interaction is represented by waiting for input, and idle has no phase label. Source-dispatch approval, submission, nonexecution and submission uncertainty remain operation states before a bound execution result is available. Historical dispatch rows remain openable and retain their own turn result while the conversation continues. Opening a dispatch selects its bound turn, labels that turn and its duration in the header and expands its timeline turn without borrowing a newer turn's live state.

A held writer with a confirmed ARC or Desktop owner may show a compact ownership label. Unknown owners and unidentified external writers have no inferred identity label. The task UI has no handoff-history popover. Native writer authorization and recovery keep their existing boundaries.

Reviews retain their recorded verdict, author, timestamp and optional note. They do not certify execution completion. Review reads are on demand.
