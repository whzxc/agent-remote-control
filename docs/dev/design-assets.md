# Design asset mapping and status

[Governance and direction](design.md) · [SDG asset rules](https://github.com/whzxc/svg-design-gallery/blob/main/docs/asset-rules.md#adopting-an-existing-project)

## Status conventions and scope

Review and adoption are separate. **Pending** means the current asset has not completed its assigned governance review. **Awaiting Claude** means the proposed structural family awaits control-source review. **Reviewed** requires Claude's approval; visual differences or open decisions also require user gallery approval. **Adopted** means a design composition or mapped implementation consumes the part. **Unknown** means the named counterpart or consumer is unresolved. A specimen alone is not a consumer. Existing usage does not imply a reviewed visual match.

The active scope is **the input family: Field/Input, CopyField, SearchInput, Switch, their tokens and representative fixtures**. The input family awaits Claude's structural review. Button and IconButton are Reviewed. Other assets remain pending their owning batch. Codex owns proposals, edits, mappings and self-inspection; Claude owns control-source review; the user owns gallery approval of visual differences and open decisions. Implementation work is outside this scope.

Queued scopes: panel/card family; choice family; feedback family; brand icons; then one feature module at a time (model configuration, quota, task presentation, task relationships, request, timeline). Continue with onboarding and individual business modules before composed surfaces. Finish with the topology module/fixtures and each homepage surface. Each family owns its importers, captures, fixture extraction and mapping updates. Review composed setup forms in rounds.

### Button family support

`fixtures/buttons.ts` owns the five Button examples and two IconButton examples. Single-part frame names remain `primary`, `secondary`, `ghost`, `danger`, `pending`, `regular` and `compact`. The fixture is support data, outside gallery discovery. Components retain their named exports and all current import paths. No frame or capture references require a rename.

`tokens.css` adds shared `--control-height-compact`, `--control-gap` and `--control-icon-size` alongside `--control-height`. Button and IconButton reuse those values; explicit IconButton `size` remains a supported caller override. Runtime token adoption is pending implementation scope. `link`, `danger-outline`, disabled, active and agent presentations have callers or props but no separate declared family frames; coverage belongs to the owning future review with the current declared forms unchanged.

### Input family support

`fixtures/inputs.ts` owns the existing field values/errors, masked copy value, search placeholder and switch state examples. All five parts stay in their generic component sources and retain named exports and importer paths. `field.tsx` is multi-part: `field` and `field-error` own labeled compositions; `input` and `input-error` crop the same input content into independent part frames. Field and Input each own their default/error content under part-prefixed frame names. These component frames have no implementation captures; mapped surface frames declare the implementation fixture/capture targets.

Input and CopyField share `--field-padding-inline`; CopyField and Switch share `--control-inset`; SearchInput reuses `--control-gap`. Field/SearchInput icon dimensions use `--field-icon-size`; their numeric SDG Icon size remains 14 to preserve the toolkit's absolute stroke normalization. Field owns `--field-error-gap`. Switch owns its width, height, thumb size and radius tokens, and keeps a circular thumb with `rounded-full`. These values retain current geometry. Runtime token adoption and the source differences listed per part belong to implementation scope.
