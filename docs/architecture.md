# Architecture

React + Tauri + Rust provides a single native core for connection state, MCP requests, idempotent receipts, and user logs. The frontend runs in the system WebView; the main application package includes no Node/npm/node_modules. Claude ACP components and a private Bun runtime are downloaded into the application data directory on explicit enable; they reuse the installed Claude executable and run only as task-owned children.

`runtime` starts one leased, file-locked Core executable per state directory. Connector CLI processes and Connector Desktop are local clients of its authenticated loopback API. Desktop owns only its GUI/tray/native panel. Local HTTP uses Hyper with bounded bodies and chunked decoding; Host accepts 127.0.0.1 or localhost on the bound port, while bearer-token and Origin checks remain enforced. The final local lease closing shuts down Core; different native builds cannot share a live owner.

`service::Service` owns the only Control and AgentHost, a shared `execution::Execution` dispatcher, and a map of `ingress::Ingress` runtimes. Ingress calls the dispatcher with domain values; the MCP transport applies result storage and the pure `egress` envelope/error projection. The dispatcher is the application composition boundary; `kernel` contains provider-independent origin, policy, receipts and result storage. Each ingress owns its lifecycle lock, listener, provider child, temporary directory, URL, logs, error and verification challenge. Runtime failure or stop affects only that ingress. Core shutdown closes all ingresses, then AgentHost and Control. Desktop-owned Codex tasks retain Desktop ownership.

Control source (a client label), transport, and authentication are independent. OpenAI Secure Tunnel uses its official identity; its stdio adapter forwards to the desktop local `/mcp/<ingressId>` endpoint with the private management credential. HTTPS listeners expose only `/mcp`, never the management API. Every listener captures its ingress at creation; requests cannot select another ingress with headers or arguments. All listeners enter the same MCP dispatcher and shared execution core. A separate listener per ingress keeps provider routing and authentication explicit without cloning the execution core. Cloudflare Quick, ngrok, Pinggy, and LocalXpose use ephemeral loopback ports; Cloudflare Fixed uses its configured loopback port, matching the remote route. Custom Domain uses a configured listening address/port. Duplicate bound ports fail explicitly.

HTTPS supports `none`, independent `bearer` credentials and OAuth with PKCE, DCR/preregistration and local app consent via clc:// or authenticated CLI consent. Invalid credentials return 401 without details. Protected local secret files are separate from ordinary configuration; status and logs do not expose secrets. Tool policies are `all` or an allowlist and apply to both discovery and invocation. The tool registry also owns editor groups, preset membership and required readers. The authenticated local `GET /api/tool-catalog` returns the full inventory independently of ingress policy; the editor expands restricted selections into explicit allowlists. They do not provide task/user isolation: every allowed task tool sees the shared namespace. Slack identity and per-user RBAC are not implemented.

The dispatcher scopes a `kernel::origin` task-local origin containing ingressId, controlSource and authType. It records this context in new operation receipts and Agent tasks, propagating it explicitly to background operations. A label is not an authenticated person; bearer proves possession only. Existing tool schemas do not require an origin argument. Wait request cancellation is scoped to an ingress; within one stateless ingress, simultaneous wait IDs must be unique.

`ingresses/index.json` identifies persisted entries. Each entry has its own config, protected secrets, verification and logs. On first load, a 0.6.x single connection becomes `default` with the default tool allowlist; HTTPS remains unauthenticated and OpenAI keeps its identity. After successful migration the legacy connection/verification files are removed. The UI's primary-connection fields are a projection of the default ingress (or first remaining ingress), not a second persisted model. The global summary reports running/ready/total independently of individual errors.

Codex Desktop owns tasks by default. Disabling Automatically open Codex tasks assigns new tasks to Connector's app-server. Ownership is persisted; toggling the setting does not move existing tasks. Desktop resume requests are ignored with resumed=false; only Connector-owned tasks can resume in its app-server. Background sends read thread status, query only the latest turn when active to select steer, and automatically resume before turn/start only when notLoaded. Ingress start does not require a Codex session: drivers initialize on demand. Read, send and wait through another ingress retain original task ownership.

The tool definitions in `native/src/catalog.json` are embedded in Rust builds. Tool validators are compiled once per tool. Writes accept optional requestId (generated UUID when omitted) and have persistent receipts, with request-ID locks around reservation and only short map locks for job registration. Writes wait up to 25 seconds by default (waitMs: 0–120000); only a longer operation returns pending. Explicit rejections and local failures are rejected/failed; unconfirmed denotes a submitted request whose outcome was lost to a transport failure. Upstream callback results are forwarded without local response-schema generation. Large outputs use immutable JSON snapshots managed by `kernel::results`. Reads preserve UTF-16 offsets while decoding in bounded memory. Results over 64 KiB inline about 48 KiB of JSON text with outputId and nextOffset; control_output reads up to 65536 UTF-16 code units per page. Snapshots expire after one hour; writes evict oldest snapshots to stay within a shared 64 MiB quota. Native JSONL event logs are excluded from snapshot eviction. Persistent events are separate from UI logs, which omit routine protocol handshake noise.

Control shares one Desktop IPC connection with readers, writers and waiters, and reconnects lazily after disconnection. Socket type/user and response-source checks remain mandatory. Invalid JSON frames and unsupported broadcast versions are skipped. Snapshots expire four seconds after receipt. Reads refresh missing or expired snapshots through owner discovery and follow/wait; incomplete requested history triggers history retrieval. Owner changes and IPC disconnection clear cached state; reconnection starts with an empty cache. Each Desktop send first performs a lightweight read (complete=false), using a fresh cache hit or refreshing through follow/wait. It uses the returned snapshot to select an in-progress turn for steer; mutate reuses the populated cache for model/collaborationMode inheritance without full history. New turns also capture a Git HEAD/dirty baseline before submission; steer retains the existing baseline. Only read failure falls back to empty state and Desktop start/default selection. Sending does not open a window or fetch full history. IPC connection does not require an installation at a fixed path. External task management supports macOS and Windows. See [desktop lifecycle](desktop.md) and [MCP tools](tools.md).

Task approval is an optional confirmation flow controlled locally or from the cloud. Request content, approval decisions, and submission state share persistent receipts. Tasks groups requests by threadId and reads native runtime snapshots without parsing conversation JSONL. Approval settings persist independently, can change while connected, and do not change Codex execution permissions.

`native/src/waiter.rs` provides a shared read-only waiting engine. The Codex adapter stays attached to the task's App Server or Desktop owner. Notifications wake the waiter; fresh native snapshots determine state, with a two-second fallback check. Truncated buffers, missing notifications, and coalesced events do not affect the final classification. Reads and waits do not hold a global lock. Cancelling drops the wait future without interrupting the turn. Connector shutdown notifies waiters through a watch channel.

`ingress/config.json` is shared by Rust and React. It defines field defaults and size limits, secret presence flags, provider modes and credential requirements. Persistence, validation, credential redaction and provider form controls consume this descriptor. Provider process startup remains in its existing runtime adapter.

## Agent boundaries

The shared dispatcher sends `agent_*` routes to `AgentHost`; existing `codex_*` routes still go directly to `Control`. The Host owns common task identity, confirmation, and lifecycle. Control and Host share `kernel::receipts::ReceiptStore` for UUID validation, durable reservation, digest conflict checks, replay, restart uncertainty and checkpoints. They retain separate receipt directories, share request-ID reservation locks, and use the same compact public projection. An operation receipt completing does not imply that its submitted task has finished. CodexNative is used only for local inventory and management; public agent_* tools reject codex and do not adapt Codex operations.

`agents/builtins.json` and user manifests share a strict Manifest type for launch arguments, discovery, version probing, and compatibility. Static descriptions do not claim negotiated capabilities. `AgentDriver::Acp` shares descriptor-driven discovery/startup and negotiates ACP v1; `AgentDriver::Pi` uses official RPC. They share bounded JSONL transport while handling responses and completion separately. Each task has its own process; raw sessions and CLC identities persist separately. Restarting a process never automatically replays unknown writes. See [Local Agents](agents.md) for capabilities and limits.

`agent_wait` and `codex_wait` expose resumable bounded event-driven long polls (30-second default; codex_wait maximum 90 seconds to leave remote gateway headroom, agent_wait maximum 300 seconds). Clients should use 20–30-second slices, retaining the same task/thread and turn IDs and passing each snapshotHash as expectedHash after timeout; timeout never stops or recreates the task. ChatGPT, Notion, Slack and other MCP clients can have different outer tool-call deadlines; no per-client timeout configuration is required. Both tools share waiter timeouts, event wakeups, periodic checks, snapshot hashes, and condition evaluation. Codex delegates to its native wait entry point. Pi/ACP use a lightweight `WaitSource` over existing Host/Driver process observations without starting or resuming tasks. Pi checks `get_state`; ACP uses live process protocol state and the final prompt response. Waiting holds no global lock. MCP cancellation and disconnect release only the current wait. Local HTTP waits explicitly race execution against EOF/error on a duplicate socket handle after consuming the request body; cancellation drops the wait future and its ingress request-ID registration. This does not depend on Hyper dropping a pending service future. The local HTTP endpoint serves one request per connection.


Project facts support an explicit Review view with canonical workspace paths, resource-boundary filtering and optional best-effort observation metadata (includeSource=true). Metadata is collected once and Git observation failure does not block file reads. Project ID/name resolution caches project/list for 30 seconds. It does not change host permissions or provide user isolation. `agent_context` is an on-demand projection over non-Codex AgentHost records and current Git facts; it owns no tasks or persistent semantic state. Evidence, claims and missing coverage remain distinct. Shared diagnostic projections derive scoped findings from existing ingress/Core observations and perform no repair actions.

## Native usage panels

`usage` streams device-local subscription history one task at a time. Compressed checkpoints retain file identity, complete-line offsets, boundary fingerprints and incremental counting state on disk. Copies of each task are merged before counting; modern response IDs define the counting family, while legacy snapshots remain an explicitly limited fallback. Parsed tasks are released after aggregation rather than retained in an all-history memory index. Only the recent 32-day events are used for subscription summaries. UI snapshots contain exact quota-cycle samples and period/model summaries instead of the raw event timeline; samples are invalidated when their time boundaries no longer match the current quota reading.

The menu-bar and tray icons open the main window on left click and a native action menu on right click; they do not own a WebView. Hiding the usage rail releases its WebView and native panel; showing it recreates them from the saved preferences. The main WebView can retire within an idle polling interval after closing, provided it has no form, dialog or update in progress. Reopening restores the page and queues navigation until frontend listeners are ready. Background connections and the visible usage rail remain owned by the desktop/Core. Once the rail has settled closed, its actual WebView canvas shrinks around the rail; expanding restores the screen coordinate space used by the primary and secondary bubbles. The desktop wakes a retired main surface invisibly each hour to preserve the existing updater's checks and preferences; it retires again when idle. Reading history, opening windows and checking updates may temporarily increase memory above the background steady state.

Local ChatGPT Desktop plugins are owned by the independent [Usage](https://github.com/whzxc/chatgpt-usage-plugin) and [Kanban](https://github.com/whzxc/chatgpt-kanban-plugin) repositories. Connector does not embed or distribute their runtimes.

Public MCP receipts are projected separately from durable storage: request ID, state, operation, task/turn IDs, necessary results and errors only. Inputs, prompts and internal execution metadata are omitted. `receipt` resolves the operation owner from the stored record. Default tools use the existing allowlist policy; advanced tools require All or Custom, and non-Codex tools are additionally gated on local availability.
